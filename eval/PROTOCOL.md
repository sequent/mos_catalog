# Протокол независимой оценки 

Нынешние 40 запросов (`eval/queries.yaml`, набор `internal-regression-v1`) использовались при принятии решений об изменениях: это **внутренняя
регрессия**. Для независимой оценки нужен **новый набор**, подготовленный другим человеком. Прогон считается независимым только при выполнении всех пунктов.

## 1. До первого прогона (записывается и не меняется)
1. **Автор набора** — человек, не участвовавший в разработке системы; **эксперт** (специалист заказчика) проверяет допустимость замен.
2. **Состав**: не менее 20 запросов: 12 с ответом в базе и 8 без допустимого ответа. Включить: близкие отрицательные (тип есть, значения нет); другой регистр и написание единиц
   (`Вт/вт/W`, `кВА/ква`, `Ду/ду`); сокращения; неполные запросы; комплекты; неизвестные типы; запросы без характеристик. Это предлагаемая композиция.
3. Для каждого запроса записать: ответ (`answer_rows`) или причину отсутствия (`answer_note`), критические значения (`eval/judgments.yaml`, формат `eval/judgments.py`),
   для отрицательных — `absence_checks` и `variants_checked` (как в `eval/queries.yaml`), а эксперт — `expert_decision`.
4. **Не подбирать формулировки по поведению движка** и не запускать систему на этих запросах до заморозки.
5. Шаблон файла: `eval/independent_template.yaml` (поля `usage: independent`, `independence: independent`, `reviewed_by: <ФИО>`, `frozen_commit`).

## 2. Заморозка
Зафиксировать commit (`git rev-parse HEAD`), убедиться, что `git status` чист; записать commit в `frozen_commit` набора. Код, `config/rules.yaml`,
`config/dictionaries.yaml` и каталог после этого не меняются до прогона.

## 3. Один итоговый прогон
```bash
.venv/bin/python -I eval/evaluate.py --queries eval/independent_v1.yaml --run-id independent-v1
```
**До первого поиска** `evaluate.py` проверяет (`eval/runguard.py`), и при нарушении завершается, не построив движок и не создав каталог прогона: набор просмотрен
(`reviewed_by`), заморожен на выбранном коммите (`frozen_commit`), все запросы заполнены, рабочее дерево чистое (ни изменённых, ни неотслеживаемых файлов кода).
Затем в `manifest.json` пишется статус `started` с коммитом, SHA-256 набора и входов, списком неотслеживаемых файлов кода (с хешами) и `code.diff`, если дерево
менялось; ответы пишутся в `answers.jsonl.gz` сразу по мере получения (полные, с `comparison` и `evidence`); при сбое статус `failed` и причина.
Каталог прогона `reports/quality/runs/independent-v1/` содержит отчёт, `results.json`, `manifest.json`, `answers.jsonl.gz` и копии входных файлов. Прогоны не перезаписываются.

**Журнал использования набора** `reports/quality/set_usage.jsonl`: первый запуск файла набора (по SHA-256) фиксируется там сразу. Любой следующий запуск того же файла,
под любым `--run-id`, отчёт называет повторным прогоном и регрессией, а не новой слепой попыткой.

## 4. Слепая разметка
```bash
.venv/bin/python -I eval/make_blind_sheets.py --from-run reports/quality/runs/independent-v1 --queries eval/independent_v1.yaml --out eval/blind_sheets/independent_v1.csv
```
Лист строится из `results.json` **уже сохранённого прогона** (`--from-run`), системы заново не запускаются. Лист не показывает, какая система вернула строку, её оценку и вердикт. Проверяющий заполняет `relevance`, `critical_values`, `evidence_text`, `reason`, `author`;
записи переносятся в `eval/judgments.yaml`. Пока пара не размечена, `technical_error@1` показывает «не оценено», а не «ошибки нет».

## 5. После прогона
Любое исправление по ошибкам этого набора превращает его в регрессионный: поменять `usage: regression`, записать это в журнале и подготовить следующий независимый набор.
Пока независимого участника не было, отчёт называет замер «внутренней регрессией».
